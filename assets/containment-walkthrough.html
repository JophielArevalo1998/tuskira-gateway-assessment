Off-policy agent → autonomous containment

A validly-authenticated agent reaches for tools its profile forbids. Here is exactly what happens, step by step, until its key is revoked and it’s cut off — no human in the path.

Attacker · the attack

A compromised agent probes off-policy tools

A valid agent API key presents the Echo Only profile, then calls an off-policy tool once per second. Credentials are real; the behaviour isn’t — exactly what a hijacked agent looks like.

Gateway · enforce + log

Each off-policy call is denied and logged

The key authenticates fine, but list-secrets isn’t in the Echo Only allow-list, so the gateway denies the call and records it. The call never reaches the everything MCP server.

authztool not in profile → −32003 (HTTP 200 envelope) sinkaccess log → stdout feed + ClickHouse reachblocked before the MCP connector
2
Bridge · detect

The bridge counts off-policy denials per key

Tailing the telemetry over a rolling window, the bridge flags compromised_agent once one key crosses 3 off-policy denials. In the live run it logged at the 5th–6th — the threshold is 3, but the feed arrives in batches, so it fires on the batch that crosses it.

detectorcompromised_agent trigger≥ 3 off-profile denials from one key windowrolling · per-principal

AiSOC · investigate

AiSOC investigates and recommends

The bridge hands the incident to AiSOC, which runs its four-agent pipeline and returns an analysis plus a recommendation. AiSOC never touches the gateway itself — it produces the finding and the recommended action.

pipelineDETECT → TRIAGE → HUNT → RESPOND confidence83/100 · MITRE T1069 / T1078 recommendrevoke_key noteAiSOC default: await human approval

Bridge · respond

The bridge executes the revoke

Under its own policy gate, the bridge auto-executes the action against the gateway’s control-plane API — overriding AiSOC’s “await approval” default because this one is single-identity and reversible.

actionDELETE /api-keys/{id} → 204 No Content gateAUTO_TIERS = low  (auto-execute) scopesingle identity · reversible · low blast radius

Gateway · key store

Key revoked → the agent is cut off

The key now carries a revoked_at timestamp, propagated instantly across the gateway. The agent’s very next call no longer fails at authorization — it fails at authentication.

statekey → REVOKED (revoked_at set) next calltools/call → 401 Unauthorized resultagent cut off · loop closed
