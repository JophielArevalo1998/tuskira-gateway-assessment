Tuskira assessment · attack catalog

Five attacks, one loop

Every attack run live on a local kind cluster against the Tuskira AI Agent Gateway, with the bridge + AiSOC closing the loop. Each card is one attack: what it does, how the gateway responds, what the bridge does, and the finding — plus the script and session id to reproduce it.

To reproduce any attack: have the gateway running on kind and the bridge live (python3 -u bridge.py), then run the attack’s script in a second terminal with GATEWAY_ADMIN_KEY / GATEWAY_API / GATEWAY_MCP (or GATEWAY_LLM) set. Each run mints a fresh key and session; the session ids below reference the demonstrated runs (look them up in Session Timeline).

Coverage: three planes (MCP tools, MCP profile, LLM) and all five bridge detectors. Attacks 1–4 end in an autonomous revoke; Attack 5 is handled by the gateway’s own lockout. The findings — payload blindness, the 200-with-error envelope, and the console’s blindness to auth abuse — came out of cross-checking the gateway, the bridge, and the console against each other.
